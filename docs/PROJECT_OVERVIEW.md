# Pet Fusion 项目总览

## 1. 项目一句话定义

Pet Fusion 是一个摄影师优先的宠物真实合成工具：使用强图像模型完成视觉重建，使用显式工程约束保证结果可控、可审片、可恢复，并保护原始旅行照片中不应改变的像素。

## 2. 典型使用场景

用户拥有：

- 一张真实旅行照片，可能包含人物、建筑、自然风景或复杂光线；
- 同一只宠物的若干参考照片，角度、焦段、姿势和拍摄条件不一定一致；
- 一个明确意图，例如“让猫坐在石阶右下角，看向镜头，像当时真的一起旅行”。

用户希望得到：

- 宠物仍然是同一只宠物，而不是同品种替身；
- 宠物的体型、眼睛、脸部花纹、毛色和尾巴等辨识特征稳定；
- 宠物与原图的机位感、主体尺度、光线方向、景深、锐度、噪点和计算摄影处理一致；
- 人物、脸、建筑、文字、构图和原始背景不被模型重新设计；
- 最终结果能回到原始照片的分辨率和摄影文件工作流。

## 3. 最初的工程构思

最初方案是一条传统视觉和生成模型混合管线：

```text
导入宠物照片
→ 自动分割和毛发抠图
→ 小模型提取或编辑动物姿态
→ 导入真实旅游照
→ 读取 EXIF、焦距、光圈、ISO 和镜头信息
→ 估计深度、地面、消失点和相机姿态
→ 确定性放置、缩放、轻度透视变形
→ 颜色、景深、锐度、噪点和阴影匹配
→ 局部生成模型修复毛发、光线和接触区域
→ 回贴原始分辨率照片
```

这条思路在工程上可实现，也有若干长期价值：

- 人工位置和尺寸控制；
- 原始像素保护；
- 全分辨率裁切与回贴；
- ICC / EXIF 管理；
- 可追踪、可批量、可复现；
- 将摄影参数转成显式质量标准。

但原型也暴露了根本限制：分割、2D 姿态、透视变换和颜色迁移只能解决局部问题，无法真正重建不同相机位置下的宠物体积、毛发光照、环境反射和遮挡。弱底模的能力上限无法靠堆叠工程步骤跨越。

## 4. 关键经验结论

### 4.1 模型负责视觉正确性

强图像模型能够联合理解背景、参考主体和文字意图，并重新生成视觉上自洽的像素。这个能力是传统模块化管线无法完整复现的。

### 4.2 工程负责控制与交付

工程的价值不是把弱模型“调成”强模型，而是让强模型具备：

- 明确位置和尺寸意图；
- 多参考图资产管理；
- 候选生成和比较；
- 结构化摄影审片；
- 搜索轮数和预算约束；
- 历史最佳保护；
- 背景像素保护；
- 崩溃恢复和幂等；
- 高分辨率、ICC、EXIF 和最终导出。

### 4.3 多轮编辑会产生累计劣化

连续执行：

```text
V0 → 编辑为 V1 → 编辑为 V2 → 编辑为 V3
```

会重复重建毛发、人物、背景纹理、锐度和噪点。即使每轮只要求小改动，也会累计出现身份漂移、AI 纹理和背景变化。

因此自动搜索必须采用：

```text
Original + References → Candidate Round 0
Original + References → Candidate Round 1
Original + References → Candidate Round 2
```

上一轮候选只用于 Critic；下一轮始终从原始素材重新生成。

### 4.4 Critic 不是最终裁判

多模态 Critic 可以帮助发现问题，但不能被当成绝对美学真理。它可能：

- 为了完成任务而强行找问题；
- 偏好“更干净、更锐、更电影化”的 AI 风格；
- 对宠物身份细节判断不稳定；
- 对候选顺序产生锚定偏差。

因此系统采用：

- 固定、可版本化的摄影 rubric；
- 候选独立盲评；
- 结构化输出；
- blocking / warning / info；
- 确定性 Ranker；
- minimum improvement 与 patience；
- `no_meaningful_defect` 合法停止；
- 人工最终选择。

## 5. 新的产品与架构命题

当前项目的核心命题是：

> 模型负责生成视觉上可信的照片；LangGraph 负责搜索和决策；本地图像管线负责硬边界和摄影文件交付；摄影师负责意图与最终判断。

对应职责如下：

| 责任 | 实现方 |
|---|---|
| 宠物身份和目标姿态的视觉重建 | GPT Image 2 |
| 光线、透视、毛发和环境融合 | GPT Image 2 |
| Critic、Prompt Planner、轮次控制 | LangGraph |
| 候选排名和 Global Winner | 确定性业务逻辑，由 LangGraph 编排 |
| Mask、裁切、像素回贴 | 本地 Python 图像服务 |
| 原始分辨率、ICC、EXIF | 本地导出服务 |
| 位置、尺寸、姿态意图 | 前端 Placement Canvas |
| 最终接受与审美判断 | 用户 |

## 6. 目标用户

### 6.1 第一目标用户

- 摄影师；
- 熟悉 Lightroom / Photoshop 的创作者；
- 对真实感和原图保护敏感的宠物主人；
- 需要少量高质量成片，而不是海量低成本内容的人。

### 6.2 用户为什么不直接使用聊天式生图

聊天式产品已经能给出很好的单次结果，但专业工作流仍需要：

- 固定管理一只宠物的参考集；
- 精确表达位置和尺寸；
- 一次比较多个候选；
- 自动审查同一套摄影质量指标；
- 保存每轮 Prompt、模型和成本；
- 防止模型修改原图的其他区域；
- 回贴到原始高分辨率文件；
- 批量或重复处理一组旅行照片。

## 7. 用户体验原则

### 7.1 默认简单，控制逐步展开

初始界面只要求：

1. 旅行照；
2. 宠物参考图；
3. 位置框；
4. 姿态与朝向；
5. 一句补充意图。

高级参数应隐藏在可展开区域，不要求普通用户理解模型节点。

### 7.2 候选优于无止境微调

默认一次产生若干候选，并清晰展示：

- Critic 分数；
- 主要 blocking 问题；
- 为什么选择当前 Global Winner；
- 下一轮准备调整什么。

### 7.3 搜索不等于编辑

UI 必须区分：

- **Search**：从原始素材重新采样；
- **Local Fix**：对已选候选执行 tight-mask 小修；
- **Export**：本地回贴和摄影文件交付。

### 7.4 原图保护可验证

系统不只声称“保持背景”，而应提供：

- Mask 可视化；
- 原图/候选差异查看；
- 允许编辑区域外的像素一致性测试；
- 导出前保护状态提示。

## 8. 摄影质量维度

Critic 和人工审片共同关注：

1. **宠物身份**：脸型、眼睛、鼻子、耳朵、花纹、尾巴、体型；
2. **姿态与结构**：四肢数量、关节、重心、身体轮廓、尾巴连接；
3. **透视与比例**：相机距离感、广角/长焦观感、主体尺度、接触点；
4. **光线与色彩**：主光方向、软硬、色温、环境反射、曝光；
5. **光学一致性**：景深、锐度、微对比、去噪、HDR、颗粒、运动模糊；
6. **物理融合**：接触阴影、投影、遮挡、地面关系、毛发边缘；
7. **场景保护**：人物、脸、建筑、文字、构图和背景是否被改变；
8. **整体自然度**：是否像真实拍摄，而不是贴图或过度生成。

## 9. MVP 成功标准

技术成功不以 Critic 分数单独衡量，而以以下结果为准：

- 摄影师盲评更偏好搜索选出的 Global Winner；
- 自动多轮不会出现累计 I2I 画质劣化；
- 允许编辑区域外像素可验证地保持原图；
- 宠物能被明确认出为参考图中的同一只；
- 轮数、成本和失败状态可预测；
- 中断后能够从 checkpoint 恢复且不重复付费；
- 输出可进入正常摄影后期或归档流程。

## 10. 第一版不解决什么

- 绝对几何正确的三维相机求解；
- 任意姿态下百分百保持复杂宠物花纹；
- 多只相似宠物的自动身份消歧；
- 非常复杂的前景遮挡和透明材质；
- 无上限自动优化；
- 模型输出完全确定性复现；
- 通用商业工作流平台。

## 11. 后续演进方向

在 MVP 稳定后再考虑：

- 宠物参考图自动质量筛选；
- 为长期使用的宠物生成 canonical reference set；
- 更精细的手绘 Mask 和局部差异 Mask；
- 轻量姿态草图或方向箭头；
- pairwise Critic 与摄影师反馈校准；
- 多照片批处理；
- 多宠物和复杂遮挡；
- 历史项目中的 Critic 偏好学习；
- PostgreSQL checkpointer 和队列化部署。

## 12. 项目名称

工作名采用 **Pet Fusion**。它强调的是具体宠物与真实摄影场景的融合，而不是局限于猫。第一版仍以猫为主要测试主体，因为猫的毛发、花纹、姿态和身份保持足以覆盖核心技术风险。
